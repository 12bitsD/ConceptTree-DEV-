# JSON 错误修复机制说明

## 问题背景

MiniMax API 有时会返回包含语法错误的 JSON，导致解析失败。这些错误是**间歇性**的，取决于：
- 输入的概念名称
- AI 生成内容的复杂度
- 生成的 JSON 长度

## 修复策略

### 第一层：基础语法修复 (`_fix_json_syntax`)

**重要：修复顺序很关键！** 规则按以下顺序执行：

0. **缺少冒号** ⭐ **最常见的错误**
   - 错误: `{"name" "value"}` → 修复: `{"name": "value"}`
   - 错误: `{"root" {"id": 1}}` → 修复: `{"root": {"id": 1}}`
   - 错误: `{"items" [1, 2, 3]}` → 修复: `{"items": [1, 2, 3]}`
   - **必须在空白规范化之前执行！**

1. **空白字符规范化**
   - 压缩多余空白为单个空格
   - 移除特殊字符周围的空格
   - 统一格式提高可读性

2. **对象/数组开始后的逗号**
   - 错误: `{"root": {, "id": "test"}}`
   - 修复: `{"root": {"id": "test"}}`

3. **双逗号**
   - 错误: `{"a": 1,, "b": 2}`
   - 修复: `{"a": 1, "b": 2}`

4. **冒号后缺少值**
   - 错误: `{"a": , "b": 2}`
   - 修复: `{"a": null, "b": 2}`

5. **冒号后直接闭合括号**
   - 错误: `{"a": }`
   - 修复: `{"a": null}`

6. **双冒号**
   - 错误: `{"a":: 1}`
   - 修复: `{"a": 1}`

7. **对象属性间缺少逗号**
   - 错误: `"value" "key"`
   - 修复: `"value", "key"`

8. **数组元素间缺少逗号**
   - 错误: `}{` → 修复: `},{`
   - 错误: `]{` → 修复: `],[`
   - 错误: `}[` → 修复: `},[`

9. **尾随逗号**
   - 错误: `{"a": 1,}`
   - 修复: `{"a": 1}`

### 第二层：上下文分析修复

当基础修复失败时，系统会：

1. **分析错误位置**
   - 显示错误位置前后20个字符
   - 检查是否是常见的缺少逗号模式

2. **智能添加逗号**
   - 检测 `}` 或 `]` 后跟 `"`
   - 检测 `"value"` 后跟 `"key"`
   - 检测 `}` 后跟 `{`
   - 检测数字后跟引号或对象

3. **多次修复尝试**
   - 简单添加逗号
   - 添加逗号 + 换行
   - 记录每次尝试的结果

### 第三层：截断恢复

当前两层都失败时：

1. **找到最后一个完整对象**
   - 定位最后一个 `}` 的位置
   - 检查括号是否平衡

2. **自动补全**
   - 如果括号平衡：使用截断的 JSON
   - 如果缺少闭合括号：自动添加

## 关键技术决策

### 为什么规则顺序很重要？

1. **缺少冒号必须第一** - 因为后续的空白规范化会移除判断依据
2. **空白规范化第二** - 统一格式后，后续规则更容易匹配
3. **移除多余符号在前** - 避免与添加符号的规则冲突
4. **添加缺失符号在后** - 在清理后的JSON上工作更可靠

### 正则表达式技巧

```python
# 匹配缺少冒号（带空格）
r'"([^"]+)"\s+("(?:[^"]*)"|\{|\[|null|true|false|\d+)'

# 匹配缺少冒号（紧挨着）
r'"([^"]+)"(\{|\[)'

# 这两个正则互补，确保所有情况都能捕获
```
